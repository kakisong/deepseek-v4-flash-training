4. 训练生效性验证（数据）

4.1 验证思路（两条互补证据）

两条证据线都建立在与训练侧完全相同的 tokenization（encoding_dsv4）之上，从根上排除 train/inference 拼接差异：

  • teacher-forcing 逐 token 似然（§4.2）——留出数据、训练前 vs 训练后同条件对照，喂真实 gt（无自回归漂移），逐 token 看模型对真实续写的预测。
  • 自由生成拟合（§4.3）——让模型自回归续写，对比生成与 ground truth，并验证推理路径是否与训练对齐。

下面 §4.2–§4.4 只列数据与示例；每组数字的含义统一在 §5 用通俗语言解读。

4.3 自由生成拟合

随机抽 albaliang 数据中 plain-text assistant turn（非 tool_call、50 ≤ len ≤ 2000、prompt ≤ 4K tok）， 喂前缀给 sglang，对比生成与 ground truth。度量：exact-match (EM)、char-level Levenshtein ratio、common prefix length。

v3（训练侧精确 prefix、绕过 chat template）为准：用 miles MultiTurnLossMaskGenerator(tokenizer_type="deepseek_v4") + 模型自带 encoding/encoding_dsv4.py 渲染整段对话（与训练 sft_rollout 同一代码路径）， 在目标 assistant turn 的首个 loss-mask=1 token 处切开，把前缀 token-ids 原样发 /v1/completions （直连副本，完全不经过任何 chat template）；gt = 该 turn mask=1 区间解码。 工具 qa_fit_check_v3.py，thinking_mode=chat、drop_thinking=0（与训练 env 一致）。

5. 结论

  1. 训练前后直接对比（§4.2）：拿训练前和训练后的两个模型，喂同一批它们在训练里都没见过的数据，一个字一个字地问"下一个字应该是啥"。训练后猜对的比例从 84.5% 涨到 88.4%，"困惑度"（模型有多犹豫，越低越好）从 1.63 降到 1.42，20 个样本没有一个变差。这说明训练真的让模型对正确答案更有把握了，不是只在训练集上死记硬背。
  2. 学到的就是我们想教的（§4.4）：提升最明显的，恰好是训练前模型最拿不准的那些样本——也就是 albaliang 这批数据特有的格式、JSON 结构、工具用法。说明它学到的是这块领域里的东西，不是随便变聪明了一点。
  3. 为什么"原样复现、一个字都不差=0"不代表没学会（§4.3）：让模型自己往下写一大段，开头差一个字，后面就全跟着变了（就像背课文，第一句换个说法，后面整段都不一样）。所以指望它一字不差地复现本来就不现实；只要它预测下一个字的能力变强了（见第 1 条），就说明学到了。拿"一字不差"来衡量是不合适的。（再加一层：这是个 MoE 模型，专家路由是"硬选择"，训练（fp32 router / EP8）和推理（sglang / TP8）之间一点数值差异，就可能让某个 token 选到不同专家、提前岔开，从而放大上面的漂移——这只影响自由生成的逐字命中，不影响 §4.2 的结论。）
  4. 顺便排除了"格式对不上"这个怀疑（§4.3）：有人会担心，是不是训练和推理时拼数据的格式不一样，才导致命中率低。我们用和训练一模一样的方式拼好输入、推理时把模板关掉再测一遍，结果几乎没变（v2 ≈ v3）——所以跟格式无关。

另外，训练这条链路（梯度回传、loss mask、分布式 ckpt 存取、HF 权重转换）整体是好的，推理也已经和训练对齐。 模型能稳定写出 albaliang 专属的 tag / JSON 格式（<command>、<filepaths>、isNewTopic schema、V4 原生 <｜DSML｜tool_calls> 等），中文长文本的标题层级、emoji、列表风格也跟 SFT 数据一致。
