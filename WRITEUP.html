并行策略入门 · 16-GPU 图解

读 V4-SFT 实录之前,先用 16 GPU 模型把 6 种并行策略的"谁切什么 · 切完通信什么 · 收益代价"一次过一遍 —— 每张图自动切换 6 秒,也可以点 tab 跳到任意一项暂停查看。下方"收益 / 代价"两栏读完即可建立心智模型,后面 §6.5 的几何 reasoning 才能读得动。

每 GPU 持有一份完整模型 · 输入 batch 切 16 份
通信:每 step 一次 grad AllReduce(16 GPU 全员)

DP · Data Parallel · 数据并行

切的是: 输入 batch(N 卡分摊 batch)  |   不切: 模型权重(每 GPU 一份完整副本)

收益
  • 近线性吞吐扩展
  • 不需要改模型代码
  • 跨节点也好用(grad reduce 容忍较高 latency)
代价
  • 模型必须能装进单 GPU(权重 + 梯度 + optimizer state)
  • 每 step 一次 grad AllReduce ≈ 2× 模型大小通信
  • 284B 模型单 H20 装不下 ⇒ DP 当不了主切法,只能 DP=1 配合其他维度

TP · Tensor Parallel · 张量并行

切的是: 单个 layer 的权重矩阵(沿 hidden 维切 N 片)  |   不切: 层数 / batch / 序列

收益
  • 每 GPU 只装 1/TP 权重 ⇒ 减参数内存
  • 大 layer(V4 单层 6.6 B 参数)的唯一装下办法
  • 跟 PP 正交,可叠加
代价
  • 每个 matmul 一次 AllReduce(高频通信)
  • 通信量正比于 activation 大小,跨节点会瓶颈 ⇒ 一般只在节点内 NVLink 上开
  • TP ≥ 2 时常一起开 SP(序列并行)进一步省 activation

PP · Pipeline Parallel · 流水线并行

切的是: 层(43 层切 N 段,每 GPU 持一段)  |   不切: 单层内部权重 / batch

收益
  • 每 GPU 只装 1/PP 层 ⇒ 减参数内存
  • 通信只发生在 stage 边界(P2P send/recv 而非 AllReduce),量小、能跨节点
  • 大模型跨节点切分的主力
代价
  • Bubble(空闲) ≈ (PP-1) / (PP+microbatch-1),PP 越大 / batch 越少越糟
  • 层数必须能被 PP 整除(或用 decoder-first/last 微调首尾),43 是质数 ⇒ 简单 VPP API 几何上不可解
  • VPP / 1F1B 调度能压 bubble,需 --pipeline-model-parallel-layout 显式 16-stage 字符串绕开整除约束 ⇒ 已验证 -2.6%(§4.14)

CP · Context Parallel · 上下文(序列长度)并行

切的是: 单条样本的序列长度(64K 序列切 N 份,每 GPU 算一段)  |   不切: 权重 / 层

收益
  • 每 GPU 只算 seq_len/CP 长度 ⇒ activation 内存按 CP 倍数下降
  • 长上下文(32K / 64K / 256K)必备,无 CP 单卡 OOM
  • 跟 TP / PP 正交
代价
  • attention 跨 CP rank 需要 KV all-gather,通信 ~ KV 大
  • 32K 必须 CP ≥ 4,64K 必须 CP ≥ 8(几何被动锁,不是调优选择)
  • 只在长 seq 上有用,4K prod shape 不开

EP · Expert Parallel · 专家并行(MoE 专用)

切的是: MoE 层的 experts(256 个 expert 平摊到 N 卡)  |   不切: 共享层(MLA, embedding 等)

收益
  • 每 GPU 只装 256/EP 个 expert ⇒ MoE 权重内存 ÷EP
  • 跟 TP×PP×CP×DP 几何完全正交(EP 是独立切法)
  • V4 这种 256 expert 模型必开,不开 expert 装不下
代价
  • 每个 MoE 层一次 token all-to-all(路由 token 到 expert 所在卡 → 返回)
  • router 不均衡会导致 expert load imbalance(部分卡过载)
  • EP 调大 = expert compute 摊到更多卡,但 all-to-all 流量翻倍 ⇒ 拐点存在

SP · Sequence Parallel · 序列并行(TP 的搭档)

切的是: TP 区域之间(LN / dropout / residual)的 activation 沿 seq 维切  |   不切: 权重

收益
  • 把 TP 区域间被复制的 activation 改成沿 seq 切 ⇒ activation 内存 ÷TP
  • 零额外成本:原本 TP 边界就有 AllReduce,改成 ReduceScatter + AllGather 流量等价
  • 跟 TP 一起开,几乎是免费午餐
代价
  • 必须 TP ≥ 2,单独 SP=on 无意义
  • 对 4K shape 收益小(activation 本来就小),对长 seq 收益大
  • 本项目默认开(cluster/run.sh:190 的 --sequence-parallel),§4 性能分析数据全部在 SP=on 下测得
本项目实际用的(V4-Flash · 64×H20 · 4K prod)
TP = 8 PP = 8 EP = 8 SP = on VPP = 2 CP = 1 DP = 1

这套不是"调出来的最优",是 TP × PP × CP × DP = 64 + 单卡 95 GB + 模型 284 B 三个不等式倒推出来的近乎唯一解(详见 §6.5)。EP = 8 跟这个等式正交,是 256 expert / EP 比的独立选择。VPP = 2 经 100 步实测 step-time -2.6%(§4.14),通过 --pipeline-model-parallel-layout 显式 16-stage 字符串绕开 43 层质数 + decoder-first/last 几何不可解。长 seq shape 才会打开 CP:32K 用 CP = 4,64K 用 CP = 8,对应 TP / PP 也被压下来。

# Per-tile FP8 dequant
def dequant_fp8(packed_tensor, scales):
    h, w = packed_tensor.shape
    th, tw = scales.shape
    bf16 = torch.empty(h, w, dtype=torch.bfloat16)
    for i in range(th):
        for j in range(tw):
            tile = packed_tensor[i*128:(i+1)*128, j*128:(j+1)*128]
            bf16[i*128:(i+1)*128, j*128:(j+1)*128] = tile.float() * scales[i, j]
    return bf16

def unpack_experts(packed_w, num_experts):
    F = packed_w.shape[0] // num_experts
    return packed_w.reshape(num_experts, F, packed_w.shape[1])

Workaround E — train-loop warmup-save hook(2026-05-18,fresh + resume 双向验证 ✓):

在 train.py 的 main loop 第一个 rollout 的 train_step 之后无条件 trigger 一次 actor_model.save_model(rollout_id, force_sync=True)。无论 fresh start 还是 resume,process 内的首个 save 都落在低 iter(start_rollout_id + 1),lazy init 在低 iter 顺利完成,后续任意 iter 的 save 沿用 cached pinned-mem pool / IPC handle / CUDA stream pool。

# train.py:89-101(节选)
for rollout_id in range(args.start_rollout_id, args.num_rollout):
    ...
    ray.get(actor_model.async_train(rollout_id, rollout_data_ref))

    # Warmup save: trigger one save after the first optimizer step in this process
    # to prime dist_checkpointing's lazy init at low iter. Must run AFTER async_train
    # so precision-aware-optimizer's master_param is populated (otherwise →
    # KeyError: 'master_param'). Cost: one extra ckpt at iter_<start+1>;
    # --save-retain-interval reaps it on the next regular save.
    is_first_step = rollout_id == args.start_rollout_id
    if is_first_step:
        if (not args.use_critic) or (rollout_id >= args.num_critic_only_steps):
            actor_model.save_model(rollout_id, force_sync=True)
        if args.use_critic:
            critic_model.save_model(rollout_id, force_sync=True)
    ...

设计要点:

  • 必须放在 first async_train 之后,不是 train loop 之前。最初设计放在 loop 前,实测抛 KeyError: 'master_param' —— precision-aware-optimizer 的 master_param slot 在 first optimizer.step() 之后才填充,save 路径会读它。

bug A:V4 hyper-connection OOM @ step 0(TP=2 触发)

陷阱:ray job submit 不 shlex.quote argv

本地 launch 脚本里用双引号包 layout 字符串,通过 "${PERF_ARGS[@]}" 应该传到 ray 作为单个 argv 元素。但 ray job submit 在 cluster 端把 argv " ".join() 重组为 shell 命令再 sh -c 执行 —— 不做 shlex.quote,所以 |、(、)、* 都被 cluster shell 解释。

解决:在本地 run.sh 给特殊字符预 backslash-escape,再用单引号包装。这样:

  1. 本地 bash 单引号保留 \ 字面 ⇒ argv 元素是 Ett\|\(ttt\|\)\*11,\(tt\|\)\*3,ttL
  2. ray 空格拼接 ⇒ cluster shell 看到 Ett\|\(ttt\|\)\*11,\(tt\|\)\*3,ttL(literal backslashes)
  3. cluster sh 还原:\|→|、\(→(、\)→)、\*→* ⇒ argparse 收到干净的 Ett|(ttt|)*11,(tt|)*3,ttL
  4. Megatron 拆 | + 展开 ()* ⇒ 16 stages

没这一步,首跑直接 /bin/sh: 1: Syntax error: ")" unexpected。

6.5 并行配置的几何 reasoning(为什么是 TP=8 / TP=4 / TP=2)

初读会觉得"TP 这么大、CP 在长 seq 才开、PP 不再调大"有点反直觉 — 通用经验是"TP 通信重,只在 activation 扛不住时才开"。本节把这套配置背后的三个硬约束列出来,让读者从倒推角度看到当前并行不是经验拍,是被几何挤出来的唯一解。

6.5.1 三个不等式

固定:64×H20,单卡 95 GB HBM,V4-Flash 284B / 43 层全 MoE,Adam 已 cpu-offload。

6.5.3 关键观察

  • 4K:TP=8 不是为减激活,是为放参数。10 GB / rank 的激活 TP=2 也扛得住,但 TP=2 让单 rank ~40 GB params 没余量,4K shape 下走 TP=8 是稳态最优。这跟"通用 prior:TP 只在 activation 扛不住才开"不同 — V4-Flash 的 6.6 B/层让 TP 变成 param memory 的硬下限
  • 32K:CP=4 是被动锁,不是主动选。seq_local 必须 ≤ 8K(单 rank ~50 GB activation 上限),32K seq 必须 CP=4。CP=4 后 GPU=64 / CP=4=16,只剩 PP×TP×DP=16 可分配,DP=1 给 PP=4 + TP=4
  • 64K:TP=2 是几何唯一解,不是为 SP 选 TP=2。SP 在 TP≥2 任何配置下都开,跟选 TP=2 无关。64K seq 必须 CP=8,GPU=64 / CP=8=8,留给 PP×TP=8,PP=4 已是 V4 43 层下 layers/PP=10-11 的下限,TP 只剩 2
  • "调大 PP" 这个 prior 已经做了。4K shape 的 PP=8 就是 64 GPU 上的几何天花板,再大要扩节点

TP

  • hidden_size (4096) 必须能被 TP 整除
  • num_attention_heads 必须被 TP 整除(V4 用 MLA,head 维由 q_lora_rank/kv_lora_rank 控制,实际 ETP 才直接吃 head)

关键耦合点(改一处会"穿层"影响多处)

  • transformer_engine ABI 锁死(L4 ↔ L6):TE 跟容器自带 CUDA 强绑;pip install 任何会 pull torch wheel 的包(如 fast-hadamard-transform)都会触发 TE 重编译失败 ⇒ 所有第三方 deps(TileKernels, FHT)都用 PYTHONPATH 注入,不允许 pip install。
  • CUDA_DEVICE_MAX_CONNECTIONS=1(L6 → L5):TP allreduce 强制串行需 =1;EP overlap 推荐 =32 ⇒ 二选一,我们选 TP(EP overlap blocked,§A.6)。
  • memory_saver LD_PRELOAD(L6 → L2):miles colocate train + rollout 时,两者共享一块 GPU 显存池;关闭这个 hook 等于 colocate 立刻 OOM。
  • Megatron PYTHONPATH 覆盖(L0 → L3b):容器自带 /root/Megatron-LM 是 miles-main HEAD,缺 sqrtsoftplus PR#28;$V4_MEGATRON 走 CFS dsv4-pr28 分支,PYTHONPATH 必须前置。

  • plugin ↔ Megatron model spec API(L4 → L3b):plugin 里的 attention 模块如果不实现 backward_dw callable,Megatron EP overlap 路径直接 fail ⇒ §A.6 EP overlap blocked 的根因在这条边上。
