DeepSeek-V4-Flash SFT 效果评测方案

Infra 团队 × 优图同学  |  起草日期: 2026-05-27  |  对象: DeepSeek-V4-Flash albaliang agent SFT（hf_iter400） |  服务: 16×TP8 sglang + router

现状：已从 pipeline / 似然视角证明"训练生效"（teacher-forcing 留出数据 NLL −28.5%、20/20 无退化，见 QA 报告）。 本方案把它升级为产品级"效果"评测——拆成两条腿：① 评测基础设施精度（尺子准不准，Infra 主责）、 ② 训练质量（模型好不好，优图主责、Infra 提供管线）。第一条腿是第二条腿可信的前提。

1. 总体框架

条腿回答的问题主责关系
① 评测基础设施精度测出来的分，是否反映模型真实能力（而非管线 bug）？Infra② 的前置；不过关则所有分数不可信
② 训练质量模型到底好不好？领域增益多少、通用是否退化？优图（建模）依赖 ① 提供的可信尺子与管线

颜色约定：蓝=Infra、橙=优图、绿=联合。 每个任务给出做法 / 验收标准 / Owner / 依赖·交付物，便于排期与验收。

2. 第一条腿：评测基础设施精度（Infra）

目标：消除"把好模型测差 / 测出假象"的所有管线性误差。按优先级排列，前三项是上线评测前的硬 gate。

#任务做法验收标准Owner依赖 / 交付物
1.1训练-推理拼接一致（chat_template gate） V4 的 tokenizer_config.json 无 jinja chat_template，sglang 默认模板 ≠ 训练的 encoding_dsv4。把 encoding_dsv4 的渲染逻辑写进 chat_template（含 system / 多轮 / tool 序列化 / thinking 模式），使 chat-API 的拼接逐 token 等同训练。 同一批样本：chat-API 渲染的 token-ids == 训练 MultiTurnLossMaskGenerator 渲染（逐 token 对齐，diff=0）。 Infra已有 qa_fit_check_v3.py 作对照；交付 chat_template + 校验脚本
1.2数值保真 核对服务端（sglang BF16 / KV fp8 / MoE 路由 / cuda graph）与参考前向的 logprob 偏差；评测统一 greedy(temp=0)，采样类固定 seed。 抽样 prompt 的 per-token logprob 与参考（训练框架或 HF 前向）平均 KL / NLL 偏差 < 设定阈值；greedy 输出可复现。 Infra复用 qa_teacher_forcing.py（已有 return_logprob）
1.3解码 / 解析口径统一 固定 max_tokens、stop/EOS（V4 <｜DSML｜…> 特殊 token）、答案抽取（正则 / JSON）；agent 任务正确解析 <｜DSML｜tool_calls｜>。 解析失败率 ≈ 0（人工抽检 N 条，无因解析导致的假阴性）；解码参数固化在 harness config。 Infra统一 harness 适配层（V4 输出格式解析器）
1.4可复现 + 防污染 钉死 ckpt / 镜像 / harness commit / 数据版本，全部入日志；跑 N 次报 mean±std。对 albaliang 训练集与 benchmark 做 n-gram / 近重去重。 同配置两次结果在方差内一致；benchmark 与训练集重叠率低于阈值并出报告。 Infra交付污染检测脚本 + run 元数据记录
1.5golden-set 回归 维护一小批固定输入 + 期望输出，每次部署 / 改配置自动跑，专抓"模板或精度悄悄改导致质量塌"。 golden-set 通过率 100%，任何回归在部署门禁拦截。 Infragolden_set.jsonl + CI/门禁脚本
1.6批无关性 验证同 prompt 在不同并发 / 批组成下输出一致（MoE 路由对 batch 敏感）；评测建议 batch=1 或先证不变性。 同 prompt 跨 batch 大小输出一致（或偏差在阈值内并记录）。 Infra批不变性校验用例

3. 第二条腿：训练质量（优图主责 · Infra 提供管线）

#任务做法验收标准Owner依赖 / 交付物
2.1benchmark 选型 领域：从同分布留出集构造 agent eval（端到端任务完成、工具选择/参数正确、schema/格式合法）。通用回归护栏：MMLU / GSM8K / HumanEval / IFEval 等，防灾难性遗忘。 领域 + 通用两套 benchmark 冻结成版本化数据集，含评分脚本。 优图依赖 1.1–1.4 的可信管线
2.2base vs SFT 同 harness 对照 对照组 = 训练起点 DeepSeek-V4-Flash-bf16-unpacked，实验组 = hf_iter400，同一 harness 全跑；有 prod / 参考模型一并比。 每个指标都有 base / SFT / Δ 三列，并标注是否显著。 联合已有 teacher-forcing base-vs-SFT 范式，扩到任务指标
2.3指标分层 任务成功率 / pass@k、工具调用准确率、格式合法率、留出 NLL/ppl（连续低方差、适合追踪）、开放题 LLM-judge 或人评。 每层至少一个主指标 + 置信区间；judge 标注偏置已校准。 优图—
2.4checkpoint 扫描 每个存档点都评，看质量曲线、抓过拟合、选最优 ckpt。前置缺口：当前 save-retain off-by-one 导致中途 ckpt 被删、只剩 iter400，需先修复才能多点扫描。 修复后训练产出 ≥3 个可评 ckpt；质量-步数曲线产出，最优 ckpt 有据可选。 联合阻塞于修 save-retain（见 §5）
2.5统计严谨 + 人工抽检 样本量保证置信区间够窄；采样类多 seed；agent 轨迹人工抽检（自动指标抓不到的质量问题）。 主指标 95% CI 报出；人工抽检报告（每类 N 条）。 优图—

4. 落地顺序 / 里程碑

  1. Phase 0 — Infra gate（先做）：1.1 chat_template → 1.2 logprob 保真 → 1.4 防污染 + 1.5 golden-set。完成后"分数可信"成立。
  2. Phase 1 — 质量基线：2.1 选型 + 2.2 base vs SFT 全跑（领域 agent eval + 通用回归），出第一版 base/SFT/Δ 报告。
  3. Phase 2 — 迭代：修 save-retain → 2.4 checkpoint 扫描选最优 ckpt → 2.5 人评 + 统计收口；按结果决定是否再训 / 调数据。

5. 复用资产与缺口

已有（可直接复用）缺口（需补）
  • qa_teacher_forcing.py：留出逐 token 似然，base-vs-SFT 对照范式
  • qa_fit_check_v3.py + encoding_dsv4 + MultiTurnLossMaskGenerator：训练精确拼接对照
  • 16×TP8 sglang + router 服务、留出样本
  • chat_template（把 encoding_dsv4 写进 tokenizer_config，chat-API 评测前必做）
  • 修 save-retain off-by-one（否则只有 iter400，无法做 ckpt 扫描）
  • 领域 agent 留出 eval 集 + 评分脚本；通用回归套件接入
  • 污染检测 / golden-set / 解析适配层脚本

6. 主要风险

  • 低估：chat_template 不补 → chat-API 评测系统性偏低（已知，列为 Phase 0 第一项）。
  • 高估：benchmark 与 albaliang 训练集泄漏 → 虚高（1.4 防污染兜底）。
  • 选点受限：只有 iter400，无法判断是否已过最优点（2.4 阻塞于 save-retain 修复）。
  • 不确定性：MoE 路由对 batch 敏感、LLM-judge 偏置 → 用 batch 不变性校验与 judge 校准缓解。
